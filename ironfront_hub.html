Game Overview
// CONCEPT · PILLARS · LOOP
// CONCEPTIRONFRONT is a tower defense + factory automation hybrid. Enemies advance along fixed paths on BTD6-style prebuilt maps. Players simultaneously build and manage a live resource-production factory to fund and supply defenses. The more you automate, the stronger your arsenal — but the factory needs space, power, and protection.

Core Pillars

⚔ ACTIVE DEFENSE
BTD6-style prebuilt maps with fixed enemy paths and defined tower slots. Tower synergies, placement, and targeting priorities all matter. No passive watching — constant adaptation required.
tower defenseplacement
⚙ FACTORY AUTOMATION
Extract, process, and assemble materials in a real logistics chain. Machines and conveyors run in parallel with the defense. A broken supply line means no upgrades and no repairs.
automationeconomy
🚛 REALISTIC LOGISTICS
Resources physically travel via delivery trucks. Truck depots pick up materials from storage and deliver to tower supply points. Bottlenecks are physical and spatial. Inspired by real supply chains.
logisticstrucks
🎮 FLEXIBLE MODES
Six distinct modes — pure TD intro, factory-only tutorial, full hybrid, hardcore, realistic simulation, and endless. Each has multiple difficulty levels with independent settings.
modesdifficulty

Map Structure

  • ENEMY PATHS — Fixed routes, BTD6-style. Visible to player before wave starts.
  • TOWER ZONES — Defined grid slots alongside paths for tower placement.
  • FACTORY ZONE — Rear area for automation infrastructure. Vulnerable to Sappers and Bombers.
  • ROADS — Pre-existing truck routes in factory zone. Expandable with road-laying tools.
  • RESOURCE NODES — Scattered across both zones. Nodes near the defense line create strategic trade-offs.

Player Health

  • Players have a set base HP — not a one-hit loss condition.
  • Different enemy types deal different HP amounts on reaching the core.
  • HP pool varies per game mode and difficulty — Easy has generous HP, Extreme has minimal.
  • HP can be partially restored between waves using resources (at a cost).
// BONUS OBJECTIVESPer-wave achievements like "Zero damage taken", "No OTL used", "All enemies cleared in under 60s" give bonus loot and meta-progression currency.

Game Modes
// SIX MODES · DIFFICULTY SCALING · STARTING CONDITIONS
// DESIGN GOALEvery mode should feel meaningfully different — not just easier or harder, but a genuinely different way to play. Starting money differs per mode and difficulty. New players enter through tutorial modes; veterans push into Hardcore and Realistic.

The Six Modes

🏗 FACTORY ONLY
Pure automation tutorial. No combat input needed — supply a pre-existing defense installation. Waves come but pre-placed towers handle them. Teaches the entire factory system with low stakes.
tutorialbeginnerfactory focus
🗼 TOWER ONLY
Pure tower defense — no factory needed. Resources auto-generate on a timer. Teaches all tower types, synergies, and wave behavior in a classic TD style. A good entry point for TD veterans.
no factoryclassic TD
⚙ STANDARD
The full IRONFRONT experience. Both factory and defense active. Scripted waves on easier difficulties, partially dynamic on harder. The primary mode with all systems enabled.
full gameall systems
💀 HARDCORE
Standard mode with tower decay, reduced starting money, low HP, shorter prep windows, and mostly-dynamic waves. Losing a key tower mid-wave can cascade catastrophically. No margin for error.
tower decaylow HPdynamic waves
🔬 REALISTIC
Deep simulation. Towers wear down and need repair drones. Higher-tier machines are more power-efficient. Real logistics constraints apply. Fully dynamic waves. Hardest base difficulty in the game.
simulationrepair dronespower efficiency
♾ ENDLESS
Separate mode — no predefined final wave. Waves escalate infinitely. Bosses appear periodically. No end boss unless the player manually triggers "Final Stand" to end their run on their own terms. Score tracked on leaderboards.
infiniteleaderboardfinal stand

Automation System
// FACTORY · MACHINES · POWER · TIERS
// DESIGN PHILOSOPHYThe factory should feel realistic — raw materials enter, get processed through multiple stages, and exit as usable components. Power generation is critical infrastructure. Without power, machines stop. Without machines, the defense stagnates.

Factory Components

⛏ EXTRACTOR
Placed on a resource node. Mines at a set rate. Upgrade for speed and yield. Requires power to operate.
inputpassive
📦 CONVEYOR BELT
Transports items between machines. Upgradeable for speed. Splitters, mergers, and filter modules allow intelligent routing.
transportfilterable
🔧 SMELTER / PROCESSOR
Converts raw materials to refined goods. Iron Ore → Iron Bar → Steel. Multi-stage chains unlock advanced tower materials.
refiningchain
🏭 ASSEMBLER
Combines refined materials into tower components or upgrade parts. The endpoint of most factory chains. Parallelizable for throughput.
craftingendpoint
🔋 POWER GENERATOR
Burns fuel (coal, oil) to power nearby machines. Essential from day one. Upgrade to solar, nuclear, or crystal generators.
powerfuel
🗄 STORAGE UNIT
Buffer storage preventing factory backups. Smart routing option auto-directs materials based on downstream assembler demand.
buffersmart routing
🔀 SPLITTER / MERGER
Splits one belt lane into two, or merges multiple lanes. Priority modes direct overflow intelligently.
belt logic
🏪 OVERFLOW MARKET
Sell excess factory output for gold. Sell only — no buying. Prevents economy bypass while giving a useful outlet for surplus materials.
sell onlygold income

Logistics System
// DELIVERY TRUCKS · DEPOTS · UPGRADE TIERS
// CORE CONCEPTResources don't teleport to towers. Delivery trucks physically travel between Truck Depots (in the factory zone) and Tower Supply Points. The speed, capacity, and route efficiency of your logistics network is as important as the factory itself.

How Delivery Works

  • Trucks follow designated road paths on the map. Roads can be extended with a road-laying tool.
  • Multiple depots on the same storage increase throughput (parallelism).
  • Trucks can be priority-flagged — set a tower as high-priority and trucks will service it before others.
  • If a depot is destroyed by Sappers or Bombers, deliveries on that route halt until repaired.
  • Traffic can back up — good road network planning matters.

Maps
// PREBUILT · BTD6-STYLE · OWN DIFFICULTY RATING
// MAP PHILOSOPHYMaps are prebuilt and fixed — like BTD6. Enemy paths are defined. Tower placement zones are defined. The factory zone is behind the defense line. Each map has its own independent difficulty rating separate from the game mode difficulty setting. Large maps so both defense and factory zones feel spacious.

Map Zones

  • ENEMY PATH(S) — Fixed routes from entry to core. Some maps have multiple converging paths.
  • TOWER ZONES — Defined grid slots around the path for tower placement.
  • FACTORY ZONE — Rear area for machines, extractors, and depots. Accessible to Sappers and Bombers.
  • ROADS — Pre-existing truck routes in factory zone. Expandable with road-laying tool.
  • RESOURCE NODES — Scattered across both zones. Nodes near the defense line create risk/reward trade-offs.

Map Difficulty Ratings

EASYWide paths, many tower slots, large factory zone, short path length.
MEDIUMStandard pathing, normal slot count, some factory obstacles.
HARDMultiple entry paths, tight tower slots, constrained factory area.
EXTREMEBranching paths, minimal tower slots, resource nodes near combat, limited factory space.

Co-op & PvP
// MULTIPLAYER MODES

Co-op Mode 1 — Open Play

// OPEN CO-OPAny player can do anything — place towers, build factory, manage logistics. Best for friends who want to work together without strict role division. No restriction on 2+ players.

Co-op Mode 2 — Divided Command

// SPLIT ROLEPlayers choose one of two roles before the map starts. At least one player must be on each side. Supports 2+ players — extra players join either side freely.
⚔ DEFENSE COMMANDER
Responsible for all tower placement, targeting priority, upgrades, and OTL weapon deployment. Cannot touch the factory — must communicate resource needs to the Factory Engineer.
towersOTLtargeting
⚙ FACTORY ENGINEER
Responsible for all extraction, factory chains, logistics (trucks, routes), and overflow selling. Cannot place or upgrade towers — must deliver the right materials to keep the Defense Commander funded.
factorylogisticsresources
// DESIGN NOTEDivided Command creates a communication meta-game. "I need 200 Steel for the Sniper upgrade" vs "I can't produce Steel until the Smelter is powered — where's the coal?" The tension and dependency IS the game mode.

PvP — Attack & Defend

// PVP MODETwo players (or teams) each have their own map mirror. Both simultaneously build defense AND produce attack units to send at the opponent's base. Kills and wave completions earn Attack Credits used to buy and send enemy units directly onto the opponent's path.
YOUR SIDE
Build defense and factory normally. Survive the waves your opponent sends while sending waves back.
ATTACK CREDITS
Earned from kills and efficient factory runs. Spend in the Attack Shop to send Rushers, Tanks, Bombers, or boss-tier units to the opponent's path.
WIN CONDITION
Reduce the opponent's base HP to zero. Can also win by surviving all natural waves if the opponent runs out of HP first.

Confirmed. Design needed: which pairs synergize, how strong the bonus is, UI visibility before placement. Must not make synergy combos so dominant they crowd out individual tower choice.
REALISTIC POWER EFFICIENCY
Higher-tier machines using less power in Realistic makes early gen crucial but late-game forgiving. Need to test if this creates fun tension or just an early frustration bottleneck.
REPAIR DRONES (REALISTIC)
Towers degrade over time in Realistic, needing repair drones from a factory-side Drone Bay. Could create interesting triage decisions mid-wave. Design not started.

The Recommendation
// TL;DR FOR YOUR SPECIFIC PROJECT
// CONTEXT: YOUR GAME IRONFRONT is a complex hybrid — BTD6-style TD maps, a deep factory/automation system, realistic logistics, multiple game modes, co-op, and PvP. It's not a small project. The engine and dimension you choose now will shape everything else, so this decision matters.
GODOT 4 + 2D (top-down)
For a solo or small-team developer starting fresh, Godot 4 in 2D is the strongest starting point for IRONFRONT. It's completely free (no licensing risk as the game grows), has a fast iteration loop, excellent 2D performance, GDScript is quick to learn, and — critically — the closest game to yours, Mindustry, is essentially a proof of concept that this exact genre works brilliantly in a 2D top-down format. BTD6 itself is Unity 2D, which is also a strong second choice if you want a larger ecosystem.

If you want more future-proofing and don't mind a harder start: Unity with 2D or 2.5D. Much larger asset store, industry-standard, and BTD6 itself runs on it.

Avoid Unreal Engine for this project. It's built for high-end 3D AAA games and would add massive unnecessary complexity for a 2D/2.5D strategy game.

2D vs 2.5D vs 3D
// CHOOSING YOUR VISUAL DIMENSION

This is actually one of the most important decisions you'll make early on — it affects engine choice, art pipeline, performance, development time, and feel. Here's an honest breakdown for your specific game.

2D TOP-DOWN
Flat overhead view. Sprites and tilemaps. What Mindustry, BTD6 (mostly), and classic factory games use. The map, conveyors, towers, and enemies are all flat — clear and readable at a glance. Easiest to develop, easiest to make readable UI for complex systems.
→ Mindustry, BTD6, Factorio, Vampire Survivors
Recommended for IRONFRONTfastest devclearest readability
2.5D ISOMETRIC
Top-down but with a diagonal perspective that gives depth. Think classic RTS games or Prison Architect. Looks more visually impressive than flat 2D, but art is significantly harder — every asset needs multiple angles, layering gets complex, and factory readability suffers somewhat.
→ Prison Architect, Hades, old C&C games
viableharder art pipelineslower to build
2.5D — 3D WORLD + 2D GAMEPLAY
3D rendered world (models, lighting) but gameplay stays on a flat plane. Looks great, feels modern. BTD6 actually does this — 3D balloons and towers on a 2D path. Requires 3D modeling skills or purchased assets, Unity or Unreal preferred, significantly more complex to make readable factory layouts.
→ BTD6, Kingdom Rush (partially), Clash Royale
looks goodneeds 3D art skillsharder than it looks
FULL 3D
True 3D camera control, 3D models, 3D pathing. Games like Sanctum 2 do this for tower defense. For your game — given the factory automation complexity — full 3D would make the logistics and belt layout extremely hard to read and interact with. Not recommended for a first game of this scope.
→ Sanctum 2, Orcs Must Die!, Dungeon Defenders
not recommendedmassive art budgetreadability nightmare for factory
// THE VERDICT ON DIMENSION Go 2D top-down to start. Here's why it specifically fits IRONFRONT:
  • Factory belt layouts and conveyor routing are crystal clear from top-down — in 3D they become a mess to read and click
  • Tower range circles, enemy paths, and delivery truck routes are all naturally expressed in 2D
  • Mindustry, the closest game to yours, is 2D top-down and it looks excellent
  • You can add depth through lighting effects, parallax layers, and visual polish without going full 3D
  • When you're more experienced, porting a working 2D game to 2.5D is far easier than starting in 3D

Languages
// WHAT YOU'LL ACTUALLY BE WRITING

Each engine brings its own language. Here's what you'd actually be writing day-to-day, and how hard it is to learn:

GDScript
ENGINE: GODOT
Python-like syntax. Indentation-based. Very readable. Made specifically for game logic — no boilerplate, short files. Easiest language to start with for game development. Not useful outside Godot, but that's fine when you're building one game.
beginnerquickgame-focused
C#
ENGINE: UNITY (also Godot)
Industry standard language (also used in .NET, web backends). Strongly typed, great IDE support. More verbose than GDScript but far more transferable. Unity uses C# for all scripting. Godot also supports C# as an alternative to GDScript.
industry standardtransferable skills
C++
ENGINE: UNREAL
Extremely powerful, extremely complex. Manual memory management, pointers, header files. Unreal's primary language. Also the most transferable language in existence — but the steepest learning curve by far. Not recommended for a first game project.
powerfulvery hardnot for beginners
Blueprints
ENGINE: UNREAL (visual scripting)
Visual, node-based scripting in Unreal. Drag-and-drop logic with no text code. Good for prototyping visually. Gets unreadable quickly for complex systems like a factory simulation — "Blueprint spaghetti" is a real problem.
visualno-codescales poorly
Java / Kotlin
ENGINE: LIBGDX (if chosen)
Mindustry was built in Java with libGDX. Java is verbose but powerful and runs everywhere. Not recommended as a starting path — libGDX has minimal hand-holding vs a full engine like Godot or Unity. Kotlin is a modern improvement on Java.
runs everywhereverboselow-level
// LANGUAGE RECOMMENDATION Start with GDScript in Godot — you'll be writing game logic within hours, not days. If you know you want Unity, learn C# — it's the right call long-term. Either way, the game logic concepts (enemy waves, targeting, conveyor routing) are the same — it's just syntax that differs. Learn the concepts, the language is secondary.

// GDSCRIPT (Godot)
# Spawn an enemy
func spawn_enemy():
  var enemy = enemy_scene.instantiate()
  enemy.position = spawn_point
  add_child(enemy)
  enemy.start_path(wave_path)
// C# (Unity)
// Spawn an enemy
void SpawnEnemy() {
  GameObject enemy =
    Instantiate(enemyPrefab,
    spawnPoint.position, Quat.identity);

    .StartPath(wavePath);

Both do the same thing. GDScript is more concise. C# is more structured. Neither is "better" — it's preference.

Where to Actually Start
// STEP-BY-STEP FIRST 6 MONTHS
// IMPORTANT MINDSET NOTE IRONFRONT is ambitious. The full game is months or years of work. The key is to build it in tiny working slices, never trying to build everything at once. Each phase should produce something playable, even if rough.
01
LEARN THE ENGINE (2–4 weeks)
Pick Godot or Unity. Follow one complete beginner tutorial series for your engine (not TD specific yet — just learn to move things, react to input, use the editor). Build a simple Pong or Breakout clone to completion. Goal: get comfortable with the editor, scripting, and build/run cycle before touching IRONFRONT.
no IRONFRONT yetjust learn the tools
02
BUILD A BASIC TD PROTOTYPE (3–4 weeks)
Build the most minimal tower defense possible: one map, one enemy type that follows a path, one tower that shoots, a wave spawner, and a health counter. Use Kenney placeholder sprites. Don't add factory yet. Don't add upgrades. Just make enemies walk and towers shoot. This teaches pathfinding, enemy spawning, targeting, and collision — all core to IRONFRONT.
pathsenemiesbasic towerwave spawner
03
ADD THE FACTORY LAYER (4–6 weeks)
On top of your working TD, add: a grid-based factory zone, one resource node, one extractor, one conveyor belt, one storage unit. Make resources actually flow. Then make resources feed into building a tower. Don't add logistics (trucks) yet — just have resources teleport for now. The goal is getting the two systems (TD + factory) to coexist and interact.
factory gridconveyorsresource flow
04
ADD THE LOGISTICS LAYER (3–4 weeks)
Replace the teleport placeholder with actual truck depots. Make trucks physically drive between storage and towers. Add road snapping. Add basic priority controls. This is where the three core loops (defense + factory + logistics) finally all work together. Get it rough but functional before polishing anything.
truck depotsroadsdelivery routing
05
MAPS, CONTENT, POLISH (ongoing)
At this point you have a functional game loop. Now expand: more tower types, more enemy types, upgrade trees, multiple maps. Add AA class. Add aerial enemies. Build the game mode selector. This is where the GDD becomes a production backlog you tick through systematically. The hard architecture work is done.
contentbalancepolish
06
MULTIPLAYER LAST (way later)
Co-op and PvP are hard. They require every game state to be synchronized across clients. Add multiplayer only after the single-player game is completely solid. Retrofitting multiplayer onto an existing single-player game is hard — but doable in both Godot and Unity with their built-in netcode systems. Don't let this block you from building the core game now.
laterco-opPvP
// THE BIGGEST TRAP TO AVOID Scope creep. The GDD is full of great ideas — dynamic waves, 6 game modes, realistic logistics, OTL weapons, alien factions. Don't try to build all of it at once. Build Phase 1–3 first. Get something playable. The rest will come. Every hour spent designing features that don't exist in code yet is an hour not spent building. Design is cheap; code is slow. Build first, design as you go.
